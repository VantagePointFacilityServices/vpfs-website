# Lead Scoring Worker

Cloudflare Worker that scores and routes leads from the two-stage gate form
embedded on this site (and on paid-traffic landing pages). Receives GHL
webhooks on four endpoints — `/gate`, `/enrich`, `/confirm`, `/outcome` — and
writes `lead_tier`/`dq_flag`/score fields back to the GHL contact.

Field structure, scoring rules, and DQ/nurture routing are documented in the
vpos repo: `commercial/docs/lead-scoring-and-two-stage-gate-form.md`.

## Local development

```bash
cd worker
npm install
npm test      # runs the Vitest suite (test/scoring.test.js)
npm run deploy  # wrangler deploy — requires CLOUDFLARE_API_TOKEN auth locally
```

## CI/CD

Two GitHub Actions workflows in `.github/workflows/`, deploying to separate
targets, per Volume 4 Section 2.5c:

- `deploy-website.yml` — deploys `site/` to GitHub Pages, unrelated to this
  Worker.
- `deploy-worker.yml` — runs `npm test`, then (on push to `main`, and only
  if tests pass) `wrangler deploy`, authenticated via the
  `CLOUDFLARE_API_TOKEN` repo secret.

**Before the worker workflow can deploy successfully:**
- Add the `CLOUDFLARE_API_TOKEN` repo secret (GitHub → Settings → Secrets
  and variables → Actions).
- Set the `GHL_API_KEY` Worker secret directly with Wrangler (not a GitHub
  secret — this is the Worker's own runtime credential):
  `wrangler secret put GHL_API_KEY`.
- Commit `worker/package-lock.json` (generated by `npm install`) so the
  workflow's dependency cache and `npm ci` step work.

**Status:** `checkDisqualifiers`, `calculateGateScore`, and `tierFromScore`
have unit test coverage (`test/scoring.test.js`) since they're pure and
network-free. Handler-level tests (`handleGate`, `handleConfirm`,
`handleOutcome`) with `writeBackToGHL`'s `fetch` mocked, or run against a
real `workerd` runtime via `@cloudflare/vitest-pool-workers`, are not yet
written — see the testing-priorities note in the field-structure doc
linked above.
